## 产品画像

老记是高频使用的个人日程与会议记忆工具，不是模型能力展示页。它应让用户快速记录、可靠找回、继续行动：

- 日程在手机本地即时创建、修改、删除、搜索和展示；语音与复杂表达可借助远端解析，但保存不依赖远端业务副本。
- 会议可来自手机录音、音视频导入或外接录音设备；来源不同，后续统一进入媒体、转写、整理、问答和行动链。
- 用户优先看到已经可用的结果。网络、模型、讲话人识别和后台恢复不得阻塞录音开始、媒体接纳或首批文字。
- 生成内容必须能回到当前会议的转写、笔记或获准附件；不以模型自信、样本关键词或漂亮版式代替来源证据。
- 页面保持干净、连续、可预测；内部阶段、provider、同步细节和重复提示不进入主界面。
- 自动恢复、清理和重试由应用负责，不以“知道了”类弹窗让用户承担内部故障。仅在确实需要权限、选择来源或其他不可替代的用户决策时打断；无法完成的结果归属受影响对象，不伪装成永久进度。
- 实现以目标效果而非最小 diff 为准：局部缺陷局部修，错误耦合、合同或算法在 owner 边界替换，不以防御性分支、额外回退或缩小验收口径应付。规范同时落在 `laoji-product-engineering` skill，不能只靠本文件或聊天。

## 数据所有权

“保留生成结果”是可选择的服务端质量改进副本授权，默认关闭，不是本机保存开关。问号说明按需展开；含义不清不作为删除选择权的理由。设备/数据域权限由服务端确认，新 Task 记录授权 revision，输出提交再核对；撤销清除副本与授权，不破坏任务恢复或本机结果，也不在重新开启时补收旧任务。见 [本轮合同与验证](../quality/GENERATION-RETENTION-20261024.md)。

| 领域 | 唯一长期 owner | 约束 |
| --- | --- | --- |
| 日程 | `laoji-schedule.db` | 与会议库物理隔离；最终 validator 和保存均在手机 |
| 会议聚合 | `laoji-meeting-memory.db` | 标题、标签、笔记、删除状态和本地关系不远端双写 |
| 媒体 | app-private media | 先持久接纳，再异步上传；原始用户媒体不因远端失败丢失 |
| 转写 | 不可变 transcript revision + active pointer | stable segment 可增量显示；讲话人是独立 overlay |
| 整理/问答 | 不可变生成版本 + 本机 active pointer | 每个结果绑定来源指纹和模型/提示词 revision |
| 待办 | 本机 `action_items` | 生成内容只是候选；用户采用后才成为可编辑对象 |
| 外接采集 | native pending media，直到本机确认接纳 | 硬件不创建会议、不直连业务服务、不成为第二 owner |

跨领域操作通过幂等 use case 协调，不使用跨库外键、`ATTACH` 事务或双写补偿。

## 当前端到端能力

### 日程

- 手动、文字与语音输入共享同一日程草稿和校验结果。
- 高置信简单表达可本机即时处理；复杂表达提交为 schedule graph，返回后仍由手机校验。
- 补充信息修改同一草稿，不把补充答案当新指令。
- 日历视图、搜索、日期选择、提醒和事件颜色只读本机事件 revision。

### 会议采集、上传与转写

单键会议/日程已采用明确手势：待机长按会议、双击日程；录制中短按暂停/继续、长按结束。用途、采集 ID、原时刻和时区持久在 RIFF 来源块中，改名和重收不改变业务去向。会议沿用自动入库，日程进入独立日程库任务和现有确认/补充/保存界面，不新增内容分类模型或硬件专用日历。文件语音适配共用现有日程 WSS + 同一 parseText，不恢复退役的 parse-audio HTTP。候选 1.2.68/276、固件 2.2.0 的构建/部署/发布和物理边界分别记录在 [本轮证据](../quality/HARDWARE-INTENT-20261024.md)，设计见 [单键合同](../hardware/SINGLE-BUTTON-SCHEDULE-DESIGN.md)。此前14项旧手势设计模型不计入当前验收。

- 导入确认后立即创建本机会议与 RecordingAsset；音频提取、哈希、R2 上传和 ASR 在后台恢复。
- 多条媒体可被并行接纳；同一资产保持 generation、journal 和幂等顺序。
- 手机录音先启动本机 `AudioRecord`，再异步附着实时 WSS；远端不可达不改变录音来源或本机成功结果。
- ASR 输出 partial/stable/final，stable 片段先持久化再确认；无讲话是成功的 `no_speech` 内容结果。
- CAM++ 讲话人识别异步执行，不阻塞文字；未知讲话人不被强行命名，人工修正不改写转写原文。
- 无登记声纹也按声音聚类。较长片段建立锚点，锚点和质心须同时相似，匿名编号按首次发言排序；登记投票冲突时保持匿名，不用静音间隔冒充身份。

### 整理、行动与问答

- 当前只有一份统一自适应整理。服务端生成结构化事实、关系、引用和行动候选；本机根据证据决定板块与图表。
- 概述、议题、结论、风险、时间线、流程、对比、数据、观点和问题按内容出现，不为填满页面而强制生成。
- 普通条目不重复展示讲话人和时间；引用在板块级收纳，点击后回到对应文字位置。
- 旧四模板字段只存在于历史 schema/迁移记录；当前运行时不读取、不转换，也不影响新任务或可见入口。
- 当前会议问答只读取该会议的转写、笔记和用户授权附件；summary 不是事实来源，无关引用必须被过滤。
- 引用由服务器按模型选出的原文片段编号生成；有答案时进行一次有界语义复核，不再搜词补证据或裁碎概括。既有答案继续绑定历史来源，不自动重做。
- 手机只合并身份与 UTF-8 范围完全一致的重复证据，并展示实际逐字范围；分句和历史来源不被改写。服务端删减证据后重新校验数字，不能继续依赖已经删掉的数值依据。
- 数字证明按实际保留的同版本连续引用读取；可识别ASR把单字数字与量词断开的词法边界，但不得拼接未引用、非相邻或被复核删除的片段。它不代替主体、否定、单位含义与相关性的语义判断。
- 新问答先用本机 binding 保存 operation、pending turn 和 activation fence，传输 owner 才进行唯一一次远端注册并核对同一 fence。不得缓存已完成的服务器确认；已有 Task 重放及本机结果激活仍走原恢复／来源校验。
- Q2完整小来源在明确协商能力后无损压缩传输，服务端有界解码后仍走同一来源校验和持久任务；不得压缩裁剪来源或借压缩绕过原inline预算。旧实际客户端保留明文表示，大来源仍由source-stream管理。
- 勾选待办只等待本机 action commit，通知和整理投影不阻塞它；关联日程只读完成状态。媒体接纳不使整理过期；实际文字、讲话人意义或笔记变化才触发更新，时间对齐、置信度和内部 ID 变化不算新内容。
- 定位接收粗略位置后的精确更新，达标即返回，粗略结果最多额外等三秒；取消/超时释放订阅，不为可选 Google 精度提示挂起页面。系统权限仍需用户决定。服务端 WGS84 转换已存在，不是本批新增。

### 外接录音硬件

以下 1.2.41/1.2.43 为历史硬件诊断，不是当前手机版本；当前交付以顶部表格与后续自动保存证据为准。第二块实板运行独立源码固件 2.1.2：I2S 采集与 SD 写盘分离，由有界 PSRAM FIFO 吸收写盘停顿，SHA/落盘/已提交实时环仍有唯一写者。两轮三分钟实板录音、暂停恢复、完整 SHA 及短范围补读对照通过；实测承接 278/378 ms 写盘停顿，不改 DMA、采样或音频完整性门。旧 2.1.0 在约 100 秒再次出现 audio_failed，源文件保留；新机制消除了采集等待写盘的耦合，但不宣称所有中断根因唯一确定或已永不复现。1.2.43 模拟器缺包/真实 ASR/同根最终结果通过，当时真机新组合尚未验收，后续覆盖见当前交付记录。设备页已有电平隔离、设备/手机错误归属、完整按钮文字、时间排序及已连接状态恢复；当前文字读取进一步移除无关 aggregate 加载，控制 GATT 拒收/超时会退出失效连接而不是永久显示健康录音。物理断电、拔卡、低电量与长时间人声质量不冒充已验收。最新实施证据见 [持续改进记录](../hardware/AUTONOMOUS-IMPROVEMENTS.md)。

- 当前唯一目标为 ESP32S3 语音备忘录 V1.0 与协作者 [BLE 1.3](../hardware/BLE-1.3.md)，旧 LJHW 帧、旧板固件和手机 USB 适配退出活动代码。

| `laoji-api` | 设备认证、capability、任务/attempt、上传编排、复杂日程解析、整理、问答、地址 | 长期复制本机日程/会议；内存任务真相；直接绕过 provider |
| `laoji-asr` | Qwen3-ASR 实时和批量协议、排队、模型 revision、稳定事件 | 会议业务状态、整理、问答 |

生成 provider 保持本地/云端可显式切换；本地失败时禁止静默把私人内容发送到另一 provider。

健康检查缓存模型可用性探针，不缓存队列、正在执行的operation或最近真实推理；这些只读同一Provider运行owner，不额外调用模型。维护准入仍以实际Task与租约为依据，等待客户端的持久工作单列，不把统计可读或队列空当作模型/任务成功。

## 状态与界面合同

- 一个操作只有一个 durable state owner。页面、列表、详情、native surface 和通知都投影同一 revision。
- 会议处理状态由整体已接受的投影revision排序，不由某个tab的加载phase或中文文案决定；页generation只保护该页内容，未打开的页面不能阻止真实任务推进。
- 状态只单调推进；页面重进、tab 切换和背景恢复不得让任务消失、回退或重复提交。
- 上一份可用内容在刷新期间继续显示。条件内容不推动固定导航、标题和选择栏跳动。
- 用户提示只表达能采取的行动；内部阶段、重复版本、构建术语、provider 原文和解释性旁白默认隐藏。
- 性能问题先找同步 I/O、重复查询、跨桥、反复解析、组件重建和双 owner，不用缩短动画掩盖卡顿。

## 当前兼容边界

历史 SQLite 迁移必须保持可重放，因此旧 account/sync/template/clip 表名和字段可留在迁移文件；它们不是运行时 reader 或 writer。旧媒体片段只保留永久删除既有文件的窄清理桥，不能恢复入口或写入。device-v1 仍是另一项有真实 caller 的过渡边界：注册/能力、部分日程与转写恢复、讲话人、删除、日程实时 WSS 和地址尚未全部切到 v2；APK 中的共享 admission token 可提取，不是秘密或授权边界。名字中遗留的 `candidate`、`legacy`、`account` 或 `template` 不能被当作当前架构依据；开发时要追到真实调用者和 writer。

## 继续开发的判断顺序

1. 当前用户行为和本机数据 owner 是否清楚。
2. 是否已有同义状态、路径、提示、adapter 或 fallback。
3. 能否在 owner 边界做垂直替换，而不是叠加新层。
4. 真实设备、真实服务和真实媒体是否验证了完整流程。
5. 新路径稳定后，旧实现是否已具备可执行删除证据。
