## 产品画像

老记是高频使用的个人日程与会议记忆工具，不是模型能力展示页。它应让用户快速记录、可靠找回、继续行动：

- 日程在手机本地即时创建、修改、删除、搜索和展示；语音与复杂表达可借助远端解析，但保存不依赖远端业务副本。
- 会议可来自手机录音、音视频导入或外接录音设备；来源不同，后续统一进入媒体、转写、整理、问答和行动链。
- 用户优先看到已经可用的结果。网络、模型、讲话人识别和后台恢复不得阻塞录音开始、媒体接纳或首批文字。
- 生成内容必须能回到当前会议的转写、笔记或获准附件；不以模型自信、样本关键词或漂亮版式代替来源证据。
- 页面保持干净、连续、可预测；内部阶段、provider、同步细节和重复提示不进入主界面。

## 全局拓扑

```text
手机本地权威
  laoji-schedule.db
  laoji-meeting-memory.db
  app-private media
        ^
        | 手机麦克风 / 文件导入 / LJHW/1 外接设备
        v
本机 repository + native platform
        |
        | 只提交领域意图、媒体或明确授权来源
        v
laoji.cloud (HTTPS/WSS)
  laoji-api :18020
    -> laoji-asr :8030
    -> Ollama :21434
    -> Cloudflare R2 staging
```

手机拥有业务实体和用户修改；服务端拥有短期计算与恢复状态。R2 对象有生命周期和清理义务，不是录音归档库。

## 数据所有权

| 领域 | 唯一长期 owner | 约束 |
| --- | --- | --- |
| 日程 | `laoji-schedule.db` | 与会议库物理隔离；最终 validator 和保存均在手机 |
| 会议聚合 | `laoji-meeting-memory.db` | 标题、标签、笔记、删除状态和本地关系不远端双写 |
| 媒体 | app-private media | 先持久接纳，再异步上传；原始用户媒体不因远端失败丢失 |
| 转写 | 不可变 transcript revision + active pointer | stable segment 可增量显示；讲话人是独立 overlay |
| 整理/问答 | 不可变生成版本 + 本机 active pointer | 每个结果绑定来源指纹和模型/提示词 revision |
| 待办 | 本机 `action_items` | 生成内容只是候选；用户采用后才成为可编辑对象 |
| 外接采集 | native pending media，直到本机确认接纳 | 硬件不创建会议、不直连业务服务、不成为第二 owner |

跨领域操作通过幂等 use case 协调，不使用跨库外键、`ATTACH` 事务或双写补偿。

## 当前端到端能力

### 日程

- 手动、文字与语音输入共享同一日程草稿和校验结果。
- 高置信简单表达可本机即时处理；复杂表达提交为 schedule graph，返回后仍由手机校验。
- 补充信息修改同一草稿，不把补充答案当新指令。
- 日历视图、搜索、日期选择、提醒和事件颜色只读本机事件 revision。

### 会议采集、上传与转写

- 导入确认后立即创建本机会议与 RecordingAsset；音频提取、哈希、R2 上传和 ASR 在后台恢复。
- 多条媒体可被并行接纳；同一资产保持 generation、journal 和幂等顺序。
- 手机录音先启动本机 `AudioRecord`，再异步附着实时 WSS；远端不可达不改变录音来源或本机成功结果。
- ASR 输出 partial/stable/final，stable 片段先持久化再确认；无讲话是成功的 `no_speech` 内容结果。
- CAM++ 讲话人识别异步执行，不阻塞文字；未知讲话人不被强行命名，人工修正不改写转写原文。

### 整理、行动与问答

- 当前只有一份统一自适应整理。服务端生成结构化事实、关系、引用和行动候选；本机根据证据决定板块与图表。
- 概述、议题、结论、风险、时间线、流程、对比、数据、观点和问题按内容出现，不为填满页面而强制生成。
- 普通条目不重复展示讲话人和时间；引用在板块级收纳，点击后回到对应文字位置。
- 旧四模板字段只存在于历史 schema/迁移记录；当前运行时不读取、不转换，也不影响新任务或可见入口。
- 当前会议问答只读取该会议的转写、笔记和用户授权附件；summary 不是事实来源，无关引用必须被过滤。

### 外接录音硬件

- App 与测试板共用 `LJHW/1` capability 协议和单一 native runtime。
- 测试板已支持 MicroSD 独立 WAV、启动恢复、S2 暂停/继续、USB/BLE 实时镜像和临时 Wi-Fi Range 接收。
- 手机可分页查看、接收、改名、确认和按 generation 删除设备文件；接收成功不自动删除源文件。
- 正式硬件沿用同一对象合同并替换为配对身份、`tls_pinned` 和真实电源能力，不能复制会议、上传或同步领域。
- 外接设备断线不会静默切换到手机麦克风；手机已有字节可封口，板端继续保存完整来源。

### 组织、删除、分享与更新

- 分类以用户标签为主；人物是讲话人派生视图，不从单次整理主题制造长期分类。
- 删除先进入本机回收站；永久删除创建远端 purge/cleanup obligation，但远端状态不能阻止本机删除。
- 分享由手机直接导出 Markdown 或所选文件。旧账号型公开链接已退役；未来若恢复，只能新增设备范围、可撤销且与删除绑定的 capability，不能恢复账号同步链。
- 版本检查以签名/哈希/大小一致的更新清单为准；版本号和构建号各有一个展示 owner。
- 独立音频片段功能已退役；原录音播放、搜索、引用与时间跳转继续保留。

## 服务职责

| 进程 | 职责 | 不得承担 |
| --- | --- | --- |
| `laoji-api` | 设备认证、capability、任务/attempt、上传编排、复杂日程解析、整理、问答、地址 | 长期复制本机日程/会议；内存任务真相；直接绕过 provider |
| `laoji-asr` | Qwen3-ASR 实时和批量协议、排队、模型 revision、稳定事件 | 会议业务状态、整理、问答 |
| Ollama | 当前本地生成模型和 0.6B embedding | 路由、任务恢复、业务持久化 |
| R2 | 有 TTL 的上传 staging object | 用户业务数据库、永久录音库 |

生成 provider 保持本地/云端可显式切换；本地失败时禁止静默把私人内容发送到另一 provider。

## 状态与界面合同

- 一个操作只有一个 durable state owner。页面、列表、详情、native surface 和通知都投影同一 revision。
- 状态只单调推进；页面重进、tab 切换和背景恢复不得让任务消失、回退或重复提交。
- 上一份可用内容在刷新期间继续显示。条件内容不推动固定导航、标题和选择栏跳动。
- 用户提示只表达能采取的行动；内部阶段、重复版本、构建术语、provider 原文和解释性旁白默认隐藏。
- 性能问题先找同步 I/O、重复查询、跨桥、反复解析、组件重建和双 owner，不用缩短动画掩盖卡顿。

## 当前兼容边界

历史 SQLite 迁移必须保持可重放，因此旧 account/sync/template/clip 表名和字段可留在迁移文件；它们不是运行时 reader 或 writer。旧媒体片段只保留永久删除既有文件的窄清理桥，不能恢复入口或写入。device-v1 仍是另一项有真实 caller 的过渡边界：注册/能力、部分日程与转写恢复、讲话人、删除、日程实时 WSS 和地址尚未全部切到 v2；APK 中的共享 admission token 可提取，不是秘密或授权边界。名字中遗留的 `candidate`、`legacy`、`account` 或 `template` 不能被当作当前架构依据；开发时要追到真实调用者和 writer。

## 继续开发的判断顺序

1. 当前用户行为和本机数据 owner 是否清楚。
2. 是否已有同义状态、路径、提示、adapter 或 fallback。
3. 能否在 owner 边界做垂直替换，而不是叠加新层。
4. 真实设备、真实服务和真实媒体是否验证了完整流程。
5. 新路径稳定后，旧实现是否已具备可执行删除证据。
