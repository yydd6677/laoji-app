# 老记能力保留矩阵初版

状态说明：`保留` 表示用户结果不能丢失；`重设计` 表示现有实现不是约束；`待验证` 表示尚未在当前发布包或真实运行环境证明。

| 能力 | 用户结果 | 当前实现观察 | 蓝图方向 | 状态 |
|---|---|---|---|---|
| 手动新建日程 | 创建、编辑、删除和回看日程 | 本机 store 与多种解析/同步兼容并存 | 本机事件内核，解析只产生草稿，不直接产生副作用 | 保留/重设计 |
| 语音新建日程 | 说完即可得到可确认的日程 | 本机录音、WSS、规则和服务解析有多级回退 | 低延迟采集、结构化语义候选、明确澄清 | 保留/重做候选 |
| 实时录音 | 立即录音、暂停、继续、停止并保留本机资产 | native recorder、realtime draft 和设备上传路径并存 | 媒体资产先落本机，处理阶段异步订阅 | 保留/重设计 |
| 文件/视频导入 | 选择后能看到上传、转写和整理的连续状态 | 上传、解码、任务和页面状态分散 | 统一资产任务编排和可观察阶段 | 保留/重做候选 |
| 文字记录 | 可持续查看、搜索、播放和跳转 | realtime_draft/final/reprocessed 多版本并存 | 统一不可变来源版本与本地投影 | 保留/重设计 |
| 讲话人 | 登记、匹配、人工修正和撤销 | CAM++、ASR、speaker store 和同步链路耦合 | 先文字可用，讲话人作为可撤销增强层 | 保留/重做候选 |
| 我的笔记 | 用户内容参与整理和问答且不被覆盖 | v3 已有部分来源载荷支持，旧路径仍存在 | 明确本机来源版本和授权边界 | 保留/重设计 |
| 会议整理 | 事实、引用、行动候选和模板视图 | v3 已有证据协议，但长会覆盖不足 | 统一证据层，模板纯投影，避免递归摘要 | 保留/重做候选 |
| 会议问答 | 只回答当前会议并给出相关依据 | 语义/词法检索和生成链路仍有耦合风险 | 证据检索、回答、引用验证分离 | 保留/重做候选 |
| 标签、搜索、分类 | 用户可管理并稳定筛选 | 历史主题映射曾与整理结果耦合 | 只依赖明确的用户元数据和来源索引 | 保留/重设计 |
| 回收站与删除 | 可恢复删除、永久删除语义清楚 | 曾有同步状态和删除入口冲突 | 本机删除事务为权威，远端清理异步 | 保留/重设计 |
| 双主题与页面交互 | 标准蓝/绚彩完整、稳定、无跳动 | 当前 UI 合同已较完整，发布证据仍不齐 | 以稳定页面骨架和语义 token 为约束 | 保留/待验证 |
| 更新与分享 | 用户可检查更新、导出和分享 | 发布清单、版本文档和源码曾漂移 | 可回溯发布快照和显式分享投影 | 保留/重设计 |
