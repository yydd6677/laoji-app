# 候选 0001：老记认知运行时收敛

状态：`rejected-as-runtime; retained-as-contract-sketch`

## 2026-08-16 独立复核决定

隔离实现 commit `92d27de` 不再是可继续加固的 durable-runtime 候选。独立复核和主代理源码复查确认：graph 只被记录而未执行，registry、trace、dedupe 和 result 全在内存，`active_evidence` 比较不构成事务 CAS，且没有持久恢复、取消、资源准入或真实 Provider 网关。

保留稳定任务身份、不可变来源血缘、单一任务 owner 和提交时来源 revision/hash 校验四项要求；不保留当前 `RuntimeCoordinator` 执行结构。详见 [持久运行时候选独立审阅](../research/0001-durable-runtime-review-20260816.md)。

## 触发原因

现场存在 18020/8030/21434 的老记链路，同时存在 11434 的 32B Ollama、8020 Smart Meeting 和多个 Tunnel/服务。源码又同时保留本地规则、旧兼容 API、v3 事实链路和多套状态投影。继续逐个优化服务会把重复边界固化。

## 目标

在不减少日程、录音、导入、转写、讲话人、笔记、整理、行动候选、问答、搜索、标签、分享、回收站、主题和更新能力的前提下，建立一个老记自有的认知运行时：

```text
本机能力/媒体资产
  -> EvidenceAsset 与版本指纹
  -> ProcessingGraph（可并行、可取消、可恢复）
  -> InferenceGateway（可交换 Provider 与资源准入）
  -> VerifiedResult（来源、版本、错误和置信边界）
  -> 本机投影与用户编辑
```

## 三种路线

### A：现有三进程内收敛

保留 18020、8030、21434，只统一任务、证据、Provider 和资源合同；旧接口退化为边界适配器。

优点是迁移风险较低。缺点是可能只是把现有复杂度搬到新接口。

### B：单一认知网关

由一个老记网关统一日程解析、整理、问答和模型调度；ASR 作为独立媒体侧车，所有业务不再直接访问 Ollama、旧 API 或模型。

优点是更容易做优先级、缓存、取消和资源治理。缺点是网关可能变成新的巨型单体，必须严格限定为编排层。

### C：本机记忆运行时 + 远端推理侧车

本机事件日志和证据索引成为权威，服务器只处理授权的不可变输入并返回可验证结果；跨设备同步不作为架构前提。

优点是隐私、离线可用性和恢复能力最佳。缺点是设备恢复、长任务续跑和多媒体存储需要重做。

## 推荐的第一原型

不直接选 A/B/C 全量重写。先做一个不接生产的“运行时回放壳”：

1. 从现有真实样本生成脱敏 `EvidenceAsset` 和任务描述；
2. 让日程、ASR、整理和问答都通过统一的 `InferenceGateway` 接口回放；
3. 记录队列等待、模型调用、证据来源、取消、失败恢复和结果投影；
4. 用同一输入比较当前分散调用与统一编排的端到端复杂度、延迟和结果一致性；
5. 不加载新常驻模型、不访问 11434、不触碰 GPU1、不改生产服务。

`EvidenceAsset` 身份必须包含资产 ID、revision 和内容 hash；任务冻结完整 `EvidenceBundle`。提交 `VerifiedResult` 时对当前 active evidence 做 compare-and-set，任何 revision 或 hash 变化都隔离整份结果。

该回放壳已经证明若干合同字段可表达，但没有证明持久执行、并行、取消或事务提交，因此不能进入生产实现；后续原型必须重写执行核心，并与现有 SQLite task ledger 做单一 owner 对照。

## 成功与否的判断

候选不能只看单个请求更快。至少要同时证明：

- 业务代码不再直接依赖多个模型端口；
- 同一来源只生成一个可追溯任务身份；
- 处理中、取消、重试和恢复只有一个状态所有者；
- 每个 durable operation 都有可枚举的注册消费者，启动时能发现悬空 outbox；
- 每个阶段声明合法状态边和跨阶段依赖，非法跃迁不能依赖 mirror 修复；
- 日程、整理和问答可共享来源与资源调度合同；
- 复杂度、延迟、质量和显存中没有以牺牲隐私或证据完整性换取的假收益。

## 明确不采用

- 直接把 11434 的 32B 当作老记新模型；
- 只把 Ollama 换成另一个 server 而不改变业务边界；
- 通过增加更多 fallback、状态字段或提示词层解决重复架构；
- 在没有独立 GPU 和回放证据时并行加载第二个大模型。
