# 混合并发验收记录（2026-08-09）

本次使用临时设备身份和临时会议，注册请求经 SSH 回环端口完成，后续上传与实时连接均经过 `https://laoji.cloud` / `wss://laoji.cloud`。后台样本为两个真实会议视频提取的 15 秒、16 kHz 单声道 WAV；实时样本为同一真实样本的 8 秒 PCM 前缀。测试结束后 7 个临时会议、数据 epoch 和临时设备主记录均删除。

## 并发负载

- 5 路设备鉴权实时 WSS，各自独立会议，按 100 ms PCM 帧实时发送。
- 2 路设备录音资产同时上传，分别创建独立转写任务。
- 实时连接共收到 10 条最终文字，全部收到 `ready_to_stop`，无服务端错误。
- 两个后台上传均 HTTP 200；两个转写任务均 `completed`，分别得到 5、4 条文字；资产 ID 和任务 ID 均唯一。

## 延迟

实时结果相对各自音频片段结束时间的延迟（毫秒）：

- p50：`1629.73`
- p95：`1846.47`
- 最大：`2049.23`

p95 低于计划中的 2 秒门槛，因此混合负载门禁通过。最大值略高于 2 秒，但门禁定义为 p95，不以单个最大值否决本轮结果。

## 边界与说明

首轮探针曾误将裸 PCM 作为 WAV 上传，服务返回 `audio_probe_failed`；这证明容器校验生效，不能作为后台链路失败。改用带 RIFF/WAV 头的同源样本后，上传、转写和清理均通过。

本证据覆盖并发调度、设备鉴权、WSS 排空、资产隔离和后台转写，不替代真实多人声纹质量、长时 soak、OOM、服务重启中的混合恢复或真机验收。

测试后的公网 `/api/ready` 仍为 `ready=true`：ASR 三类队列均为 0，Ollama 队列为 0，持久任务 worker 的 queued/running/active leases 均为 0；主库、日程库和声纹库仍为 WAL、`integrity=ok`、外键违规 0。
