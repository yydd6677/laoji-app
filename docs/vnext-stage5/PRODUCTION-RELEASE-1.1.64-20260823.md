# vNext Android 发布记录：1.1.64（172）

## 结果

- 发布状态：已开放在线更新，并覆盖安装到当前真机。
- Android：`1.1.64`，`versionCode=172`，包名 `com.laoji.app`。
- 本次只修复客户端的上传终态和增量文字投影；生产 API、ASR、Ollama、GPU 及其他服务均未重启。
- 真机原有会议、录音与已生成文字均保留，未卸载应用或清除数据。

## 根因与修复

1. v2 转写事件的每个增量前缀都复用了同一个 `${taskId}:live` 远端版本 ID。第二批开始时，
   不可变远端版本校验会把增长后的文字误判为“同一版本正文改变”，因此手机只确认首批事件并反复读取后续事件。
   现在增量前缀只更新本机可变草稿，收到 final 后才建立不可变远端版本。
2. WorkManager 的成功结果可能只被观察一次。旧流程在清理兼容队列后再次读取原生状态，可能丢失该成功结果，
   使已上传资产的本机 operation 永久停在 queued。现在先从当次结果提交远端资产 ID/revision，再关闭 operation；
   同时允许经过远端资产身份校验的 `queued -> success` 单调跨级收敛。
3. 详情页不再让旧 pending registry 覆盖 SQLite 权威处理阶段。上传、转写状态由与会议总览相同的权威状态决定。
