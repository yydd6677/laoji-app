## 显式切换与回滚合同

后续得到生产发布授权时，必须先备份生产 SQLite，再部署版本化服务目录、执行 migration、写入同一
waiver provenance 的 barrier，确认 loopback readiness 后才发布 APK。不得直接把隔离候选数据库复制
为生产数据库。

回滚以完整 release 为单位：停止新 vNext admission，保留 generic task/source 的 drain/read，部署
保留的旧 handler revision 并回发稳定 APK。禁止请求失败时自动调用 legacy，禁止重新开启双写。Stage
5A 的 adoption 前 SQLite backup 和 1.1.10 APK 都保留；Stage 5B 删除前 legacy source/table/reader 也
继续保留。
