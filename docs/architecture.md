# 架构

老记采用本地数据优先的客户端与独立计算服务。客户端是日程、会议资料和编辑状态的持久数据源；服务端负责鉴权、可恢复计算任务及模型推理。

## 组成

| 部分 | 职责 | 源码 |
| --- | --- | --- |
| React Native | 导航、领域用例、本地数据与界面 | `src/` |
| Android 原生模块 | 录音、媒体导入、播放、原生界面、后台工作及硬件通信 | `modules/laoji-native-platform/` |
| API | 设备鉴权、上传编排、任务、解析、整理、问答与地址查询 | `services/laoji-api/` |
| ASR | 实时语音识别和批量转写 | `services/laoji-asr/` |
| 模型 Provider | 生成与 embedding 适配，本地和云端配置可切换 | `services/laoji-api/app/` |
| 录音固件 | 采集、存卡、控制和音频传输 | `hardware/esp32s3-voice-memo/firmware/` |

## 数据归属

- `laoji-schedule.db`：日程、重复规则、提醒与日历投影。
- `laoji-meeting-memory.db`：会议、转写、笔记、整理、问答、标签、行动候选及任务投影。
- 应用私有媒体目录：本机录音、导入后的音频及外接设备接收文件。
- 服务端存储：设备身份、上传会话、计算任务、清理义务及允许保留的生成结果。

两个本地数据库独立迁移，通过应用用例传递关联信息，不建立跨库外键。会议行动转为日程时，由日程用例保存，并将关联结果返回会议侧。原始资料的临时服务端处理与生成结果留存是不同的数据生命周期。

## 主要流程

### 日程

文字或语音进入日程输入用例，解析结果由本机校验、编辑和保存。可本地完成的解析不依赖网络；复杂表达交给配置的模型服务。解析结果经本地校验和保存后写入日历。

### 会议

手机录音、文件导入与外接设备接收共用会议媒体用例。视频先提取音频；上传任务持久化后可恢复。转写采用稳定片段身份，讲话人识别作为异步覆盖，不阻塞第一份文字。

整理将来源转换为结构化事实、引用和行动候选，由客户端组织展示。问答以所选会议的来源版本为上下文；引用关联文字记录位置。

### 状态与恢复

录音、导入、上传和生成任务各自维护持久状态。页面、原生快照和后台工作读取同一任务状态；任务身份、来源版本和幂等键用于重试及恢复。

## 部署边界

HTTPS/WSS 入口连接 API；默认内部端口为 API `18020`、ASR `8030`、Ollama `21434`。R2 用于临时上传对象，不承载日历或会议索引。内部端口应仅监听 loopback；实际路径、模型、密钥和资源配置由部署环境提供。

模板见 [Linux 部署](../deploy/linux/README.md)，硬件合同见 [硬件接口](hardware/README.md)。
