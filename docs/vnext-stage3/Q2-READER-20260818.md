## 已闭合的实现边界

1. 服务端新增 `POST /api/device/v2/meetings/{binding_id}/questions-v2`。请求使用
   Pydantic `extra=forbid` 合同，包含 schema/provider revision、binding generation/revision、
   cancel revision 和不可变来源列表；接口默认由 `LAOJI_VNEXT_Q2_READER_ENABLED` 关闭。
2. reader 每次只调用一次 `LlmProvider`，输入只包含当前转写、用户本次勾选的“我的笔记”和来源哈希；
   不读取整理结果、旧答案或历史问答上下文。`answer` 必须由连续分句完整覆盖，所有引用必须落在
   当前来源的 UTF-8 字符边界并逐字匹配。
3. 移动端 Q2 仓储拥有 snapshot/thread/turn/clause/citation；Q2 结果不会写入旧的
   `meeting_question_*` 表。页面重进从 Q2 仓储只读投影，引用仍定位到当前文字记录或我的笔记。
4. Q2 任务使用本机 `device_operations` 作为可恢复的运行标识。失败重试更换 operation 并原子
   重新绑定 pending turn，成功后只提交一次；同一 pending 问题复用原 turn/request/ordinal，原 operation
   仍在运行时拒绝重复提交；来源 fingerprint 变化会要求新问答线程。
5. 现有问答 UI 只有在 `meetingQuestionsQ2Candidate` 与远端 `question_reader_v2` 同时开启时
   选择 Q2；默认 APK、稳定问答和服务器生产流量不变。

## 真实来源 holdout

- 新增 `tools/vnext/evaluate_q2_real_holdout.py`，以目录中的字幕窗口作为弱参考来源，不把字幕正文
  写入生产 prompt、few-shot 或规则。22 个问题通过隔离候选真实 `qwen3.5:9b` 调用，覆盖 10 个
  样本、明确未提及、部分提及和两组 transcript/manual note 明确冲突；结果 `22/22`，暖态单题约
  `0.9--4.2s`，报告为 `q2-real-holdout-20260818.json`。
- reader 对模型常见的字符下标/UTF-8 下标混用只重算逐字 quote 的服务器范围；quote 不在当前 source
  时仍 fail-closed。多子项问题允许回答已知部分并明确缺失项；最终日期/价格等在不同来源给出不同
  明确值时，在模型调用前返回 `cannot_confirm`，不选边、不产生引用。
- 这关闭了短窗口真实模型、拒答、部分提及和冲突的候选证据，但不等同于完整长会议检索、人工引用
  相关性、Android 页面/恢复或 capability barrier 通过。
