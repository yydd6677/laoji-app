# 会议问答后续改进：来源提交与输入预算

承接 `QUALITY-20261022.md` 的未闭合问答项。原待办/整理状态、定位和匿名讲话人改动不重复实施；本轮未改 ASR、固件、GPU 分配或其他用户服务。未提交、未推送 Git。

## 采用的实现

1. 普通问答新增 capability `question_inline_sources_v1`，在同一 POST 中准备来源并执行既有 Q2 Task。不是无状态旁路：来源仍写入现有 AES-GCM source stream，保留设备、epoch、binding、revision、hash、配额、租约和逐批恢复检查点，成功时仍原子提交结果并删除临时原文。
2. 合并入口限制为 1,024 项、单项 8,000 Unicode 字符、256 KiB 序列化来源；手机逐项计算预算，超出时使用现有大型来源流。不拼出多份超大正文。两种传输的 Task/stream/item/bundle 标识和哈希完全一致，中途退出可按原检查点重放。
3. 成功重放先读取原 Task，不重建已清除的来源。新操作不先请求一个已知不存在的 Task；持久 handle 仍查询远端，不能缓存服务器 authority 绕过 fence。远端 handle 的持久化回归到 transport owner，在实际提交前完成。
4. SourceBundle 的正文及 reader 输入不再被通用字符串 trim 改写，保留原始 UTF-8 哈希和引用范围。
5. 输入预算按真正发送给模型的 packed representation 计算；取消来源流独有的 4,096 token 小上限，两种传输统一使用既有 10,240 token 输入预算。模型仍是原常驻 9B，`num_ctx=16384`，没有增加上下文配置或 GPU 分配。
6. 仅用于检索的相邻短转写合并不再错误要求 segment ID 相同，原始 source 身份仍完全保留。数值校验使用 `cn2an==0.5.24` 转换独立数字 token，允许中文数字、阿拉伯数字及百分比等价；不转换整段原文、不推断单位/主体/最终状态，语义复核仍负责这些判断。

## 实际证据

样本来源是用户视频真实经 Android 导入、R2 上传、生产 ASR 转写并保存的 225 段内容；不是拿字幕替代 ASR。参考字幕损坏过最终比例，另查看视频 13:50 的内嵌字幕确认 50%；此信息仅用于评测，不进入生产 prompt/代码。

- 原 app 链路同一单价问题 39,767 ms：12 次来源准备 HTTP 请求、一次新任务 404、两次 binding PUT、模型请求 20 秒超时后轮询；答案错误采用中间报价 18 元。
- 只合并传输时 31,079 ms：来源准备合为同一个问答 POST，保留任务恢复。此时尚未采用预算修正，答案仍错；不能把速度改进称为质量通过。
- 最终采用版 Android 进程重建后的首次实际问答 16,237 ms，下一次同输入 16,141 ms；两次均只有两次 binding PUT 和一次合并问答 POST，没有新任务 404、逐批来源 HTTP 或 20 秒超时轮询，最终单价均为 20 元。相对原 39,767 ms 的一次冷态对照约减少 59% 等待。这不是 p95，不用纯模型时间替代 app 总等待。

计时边界是会话准备后的发送调用到 SQLite 保存，不含打开问答页面和首屏渲染；最终探针在计时前刷新 capability，而旧基线发送过程含约 0.8 秒 capability 请求。因此这是实际同输入发送链路对照，不是严格等条件的冷启动因果基准。Ollama 常驻模型没有重启。
- 同输入长会议 12 题真实模型回放，预算/数字修正版正确回答最终单价 20 元、12 批、每批 4 万件以及稍后签合同。但预付比例、余款期限、综合条件仍存在漏答，综合题仅留下签约/寒暄也不合格。不能称达到人工 95% 或长会议质量已经闭合。
- 原短会议真实 ASR + 当前笔记的 8 题回放均完成：概述、工作、管理流程、平台、合规、笔记、无采购条款、无电话。笔记作者和转写发言人不混同；这仍不是独立人工质量验收。
- Python reader/数值/引用/来源恢复合同 78 项通过；在实际生产模块上叠加聚焦改动的接口、来源流和恢复回归 31 项通过；前端传输、取消后不提交原文、原文引用和历史恢复 14 项通过。类型检查、UI 已知回归通过。这些数量不是语义质量样本数。
