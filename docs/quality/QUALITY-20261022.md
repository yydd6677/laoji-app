## 实现取舍

### 问答不是继续加词表

旧实现以关键词覆盖补引用、重绑定来源和裁剪枚举，导致普通概括被截碎，附近背景也可能成为引用。本批删除其专属执行逻辑与测试假设：reader 从约两千行缩至约八百行；替换为原文窗口、片段编号、服务器取原文、一次有界语义复核。无旧开关/旧 writer 或失败时词法降级。

1. 原始 source/revision/hash/binding 继续校验。长来源仍经本地 embedding 选择，不从整理结果取事实。
2. 连续转写按原序打包，禁止跨检索缺口、不同来源/版本和已知长静音间隔。模型选择窗口 `source_id` 和窗口内 `first_part/last_part`，不复制引用正文。长单条来源按 Unicode 字符无损分片，保留父来源哈希和绝对 UTF-8 范围；每条公开引用符合手机长度合同。所有回答文字只在有引用的 clauses 中生成一次，不生成另一份无引用的 answer 文本。
3. 服务器按原始成员生成 quote、哈希与 UTF-8 范围；不自动补数字或从其他位置找相似文字。
4. 一次语义复核判切题、整句支持、状态、不同来源主体、每组引用与重复事实；只整句保留/拒绝，不重新写答案。笔记的“我”不自动成为转写的发言人。
5. 有答案通常两次模型调用，无答案一次；不是递归 verifier/editor 链。输出格式/来源验证失败明确失败，不兜底返回未经验证的答案。
6. 手机不再把引用正文当作标识符 trim 或拒绝普通换行/制表符；按原始字节验证范围，不放宽来源身份或长度限制。

真实探测确认 Ollama 0.24.0 + Qwen3.5 的 chat/think=false 没有执行 Schema，甚至返回代码围栏；同一常驻模型的 generate 能执行。Provider 统一承担结构化传输选择，保留非结构化 chat、后台抢占/流关闭和显式云端 Provider；没有给每种业务各加 JSON 修补层。上游同类问题：[Ollama #14645](https://github.com/ollama/ollama/issues/14645)。

共享 Provider 的真实整理回归随后暴露 `schema_to_grammar` SIGSEGV：整理 source-ID pattern 的 `(?:...)` 非捕获分组不受运行版本支持。仅将该分组改为接受同一字符串集合的普通分组，保留全部来源 ID 约束，不做无 Schema 降级。上游对应修复说明：[llama.cpp #21124](https://github.com/ggml-org/llama.cpp/pull/21124)。修正后同一真实 ASR/笔记完成一次整理：1 次调用、6 条事实、5 条关系、1 条候选，7.684 秒；强制模型日程路径 1.832 秒，日期/15:30 正确，无 fallback。部署后不加载候选模块再验：整理 7.198 秒，模型日程 1.813 秒，结果一致。独立进程只验证生成，没有覆盖手机当前整理版本。

### 状态回到领域 owner

- `action_items` 只决定完成状态，生成投影不得重置或复活它。完成操作只等待 SQLite 提交，失效旧读 generation，再就地更新；通知异步处理，退出页面也继续必要清理，不再等待全量整理刷新。
- 增加按 native session 读取会议根的轻量方法，待办加载不读完整会议聚合。
- 转写不可变身份与“整理含义”分离。文字和有效讲话人相同，时间/置信度/内部 ID/分段变化不使整理过期；实际文字、否定、讲话人变更仍生效。严格远端 revision 内容校验未放宽。
- 媒体接纳不再读写 summary 状态。硬件的最终媒体可在实时文字之后到达，单纯补齐文件不代表出现新整理来源；文字/笔记 writer 才负责新内容失效。
- 历史 stale 修复保留笔记 revision 和当前版本事务 fence；没有足够证据的不擅自清成 ready。

### 讲话人与定位

- 无登记档案也运行 CAM++ 匿名聚类。长音频观察先建立锚点，锚点/质心同时满足相似度才合并，避免逐步漂移；按首次源时间命名，不由 worker 完成顺序决定。登记票数需超过半数且至少两票，平票不命名；短/无向量继续未识别。
- 位置 watch 在粗略 fix 后继续接收精确 fix，达标即返回，粗略结果额外等待最多三秒；超时/取消释放晚完成的订阅。未增加后台定位或绕过系统权限。
- 真正模拟器回放发现可选 Google 精度弹窗会将 App 放后台并挂住整个竞速；取消这类自动弹窗，仍使用 High 精度和原生 GPS。没有同意额外 Google 数据采集协议。
- WGS84→高德转换原本已在生产，不记成新增成果。另抑制 HTTPX/HTTPCore 的请求 URL INFO 日志，防止地理编码 query 泄露坐标/Key，保留业务脱敏耗时日志。

- 同一真实 Android ASR + 当前笔记共 **8 个问题**，实际本地 Qwen 生成/复核；最终采用版重放 **8/8 请求成功**，约 **1.4–9.9 秒**。这是服务/归因检查，不是人工 95% 质量或暖态 p95。旧同输入三题对照保留；复核有成本，不能宣称所有问题比单次旧调用更快。

## 未闭合项：不能称问答质量已全部解决

扩展长参考字幕回放仍出现中间方案当最终数值、漏答和拒答。字幕并不等于真实 ASR 或人工真值，但这些失败足以否定“已经全面通过”的说法。全局 span ID、额外角色复核、先选依据再回答、有界 thinking 均未稳定改善；thinking 三次耗尽预算无最终结果，先选依据路径遗漏后半段。以上实验实现、开关与专属测试已移除，不留备用执行链。失败结果只作为本机评测证据保留。

当前采用的是通过真实短会议调用与来源合同回归的基础替换；**长会议最终状态/数值判断和答案召回仍待改进**。这部分与已完成的待办/整理状态修正、定位竞速重构、匿名聚类修正分开报告。没有把任务范围缩成 HTTP/Schema 成功就当质量验收。
