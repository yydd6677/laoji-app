# Q2 数字边界修正与单位候选淘汰

## 已采用范围

本轮仅修正 reader 的数字 token 边界；不改生成 Schema、prompt、来源选择、语义复核、模型、公开协议或历史答案。

- `2千克`、`五千米` 中的“千”属于单位，不再错误并入数字成为 2000／5000。这样 `2公斤` 与 `2千克`、`五公里` 与 `5千米` 的数值部分可以等价；单位是否支持仍由原语义复核判断，不新增单位换算。
- 单字中文数字后面的多字计量单位被识别：如“三小时”“两公斤”“五公里”，不再因为后一个字不在旧单字量词集合中而忽略数量。
- “一千元”“2千人”“3千件”“五千万元”仍保留真实数值倍率；百分比、普通词内单字数字、原文 UTF-8 范围和来源哈希合同不变。
- 数字校验仍不是语义证明。主体、单位、否定、最终状态及问题相关性不能靠数值集合判断；没有新增关键词否决或失败 fallback。

本轮最终生产 diff 仅为两个匹配定义及现有数字提取函数的一处量词判断。reader SHA-256：`05a4de1507e26e73aed81dbb147e908234be31f3c777c76f2bb5b2786098543f`。原生产 reader 为 `b197aae415f108d98794591991bacee703f4029d13725c00f512fc105f31a79c`。

## 不采用的单位硬门禁

初始候选保留数值与显式单位的关联，试图拒绝“来源24人、回答24元”这一类不相容量纲。它是通用计量词校验，不是样本词；但仍然不是可靠的语义判定：

- 在“现场24人，停车费30元”的来源下，经过语义审核的正确回答“不是24元，而是30元”也会被单位门禁整句删除。补充合同真实触发了该误删。
- 单位省略、数值与主体关系、同义量词及否定范围都不能由这个硬判断解决。历史失败候选曾把“每批四万”写成“四万元”，原引用其实没有显式“件”，不能假称本候选能修好它。
- 不增加否定关键词例外，不继续放宽数值集合；该门禁及专属测试已完整移除，生产没有新开关、备用分支或额外调用。

## 证据边界

1. 最终 reader、窗口、语义复核、Provider 及重放／探针回归：**126 项通过**。包括真实倍率保持、中文／阿拉伯数字、公斤／千克与公里／千米的数值等价，以及已审核的否定纠正不能被字面门禁误删。这些是合同测试，不是126条自然语言质量通过。
2. 原长会议12题、短会议／笔记8题：保存的真实生成和复核输出，经最终代码零网络重放，**20/20完整 envelope 相同**。没有重新生成历史结果或再调原题 prompt。
3. 自写的计量协议诊断来源有6段文字、8个问题，分别经原生产 reader 和初始单位候选真实调用9B，共30次生成／复核；8个最终回答逐字相同，没有质量收益。最终数字边界修正版也重放这8个捕获结果，全部相同。
4. 最终数字边界修正版另做2个单位改述问题、4次真实模型调用。模型仍倾向保留原单位；综合问题仅留下重量、漏掉路程，不能称完整回答通过。以上合计10个独立自写问题、34次实际模型调用，不是自然录音样本或人工质量基准。
5. 这批诊断还暴露既有语义复核错误：来源明确说步行三小时，复核却以五公里通常走一小时的常识否决；问题问费用是否24元，来源和回答都明确30元，复核仍因问题没有24元依据而拒绝。这些错误没有被本次数值切分修正解决。
6. 另发现“统一一致”连写时，旧数值提取将相邻“一一”按11处理；这是原版同样存在的自然词边界问题，本轮没有加专用词例外。不能据本次修正宣称所有中文数值边界已解决。
