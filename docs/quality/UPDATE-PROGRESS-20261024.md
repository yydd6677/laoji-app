- 无服务端逻辑变更、重启、Git 提交或推送。已有问答质量债未关闭。

## 修正的 owner

1. 原自动检查在 AsyncStorage await **之前**判断是否下载中，恢复后可以把下载状态写成 checking；已发出的检查成功或失败也可覆盖下载。检查单飞、下载单飞和检查 generation 失效共同封闭这些竞态，不在页面中保留一份独立假进度。
2. 重复安装调用不再重建/删除同一下载文件。下载从明确的 0 开始，以本次清单中的不可变文件大小计算、整百分比变化时发布；拒绝非法值和倒退。文件验证期间保持 100%，晚到回调不能复活失败或已就绪任务。
3. 缓存目录创建失败纳入同一终态处理，避免永久 downloading。
4. 更新文字与 SettingsRow 的文字显式使用当前主题字体，统一 RN 测量和 Android 绘制。原 Activity 隐式字体并不能保证 RN 测量一致；这是一处已修正的风险，不据此宣称它是本次真机现象的唯一根因。
5. 仍只有更新说明附近的一个下载按钮，不增加重复百分比、状态栏或说明文字。

## USB 诊断：初始记录

以下是换线前的初始证据。后续保持同接口、原 ADB 换线，60轮/120MiB双向校验通过，见 [换线对照与恢复](USB-LINK-20261024.md)；不回改初始失败记录。

- 最早手机插入时（18:26:39）内核已有 `device descriptor read/64, error -71`；18:52:07 重现。首次错误早于本轮手动 USB reset。设备有时缺少可读序列号，后续恢复为同一 Redmi K60。
- 当前端口 `power/control=on`、`runtime_status=active`、`runtime_suspended_time=0`，没有支持“电脑自动休眠关闭 USB”的证据，未添加无效的全局禁休眠配置。
- 19:11 的 24 次双向 64KiB 诊断仅首轮成功；第二轮开始 USB ADB transport 不存在。其后 23 次是同一次掉线后的不可达，**不是 23 次独立断连**。该次内核没有新物理拔插事件，不能把所有 ADB 中断都归因于线材。手机 adbd PID 仍为 2103，亦不能声称已证明其崩溃重启。
- 旧无线端口随后拒绝连接，因此没有把无线恢复可用与 USB 修复混为一谈。安装与版本确认在该中断之前完成。
- 本轮主动 USB reset（18:49:18）、ADB server 重启、一次独立 LibUSB 后端与系统旧 adb 对照均属于诊断干预，不能计为自发掉线。未得到稳定改善，已恢复 SDK adb 37.0.0 的 NATIVE 后端，未替换 SDK、修改手机设置或持久化测试配置。
- 边界判断：存在低层 USB 通信异常，也存在 ADB 热插拔/恢复异常的可能，尚不能唯一定位到线材、接口、手机 USB 固件或主机驱动。SDK 37.0.1 官方修复了 Linux udev 热插拔竞态，可作为后续隔离对照，而不是已验证的修复。
