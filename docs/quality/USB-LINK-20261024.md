# 手机 USB 调试链路换线对照

## 结论

同一 Redmi K60、同一电脑 `3-4` 接口、同一原 SDK ADB `37.0.0 / NATIVE`，更换数据线后恢复稳定。故障高可信定位到原线材或其接头接触路径，非老记应用功能。未拆检旧线或再回插旧线，不进一步断言内部断芯还是接触不良。

## 证据

- 旧线：电脑仍保留 USB 设备，手机调试开关为 1，小命令偶尔成功，但随后 transport 消失；不能把手机常驻“已连接 USB 调试”通知当作连续传输健康证明。
- 隔离 ADB `37.0.1 / NATIVE`：20:12:38 执行只读 256KiB 数据请求，读 ADB header 时 USB ioctl 返回 `errno=71 (Protocol error)`，随即 `usb_read returned unexpected length -1 (expected 24)`。失败在 USB I/O 层，不是应用业务协议。
- 同版 LibUSB：20:13:37 在握手 header 读取即出现 `LIBUSB_ERROR_IO`，重枚举后读取设备 serial 仍 I/O 失败。升级或换后端未解决，故未采用这些软件候选。
- 新线：用户按要求只换线、不换电脑接口；测试保留原 ADB，不修改手机 USB 模式、授权、系统设置或用户数据。设备号 98、serial `825f509d`，全程未变化。
- 连续 **60/60 轮通过**，约 **128.16 秒**。每轮手机→电脑读取 1MiB 全零数据并逐字验证；电脑→手机发送 1MiB 含全部 256 字节值的数据，由手机计算 SHA-256 并核对。合计 **120MiB**，全在内存/管道中处理，未在手机留下测试文件。
- 同时完成截屏、USB manager 查询、安装版本查询；手机 `connected/configured=true`，主机端口 active 且未休眠。完成后额外 shell probe 成功。APK仍为 `1.2.66 / 274`，不需要为更换数据线再发布应用。

## 收尾

现行 SDK、NATIVE 后端和手机设置保持原样；临时 trace 已关闭，失败候选未替换 SDK，下载/解包的临时工具已清理。官方候选 ZIP 按仓库 XML 核对：37.0.1 Linux，9,054,187 bytes，SHA-1 `477254aa5f903c15cf51001717bdf347fb6b53e0`。不是一次软件升级交付。

详细原始结果：`output/usb-diagnosis-20261024/new-cable-soak.jsonl`；旧线对照：`candidate-37.0.1-soak.jsonl`、`usb-failure-extract.txt`、`kernel-events.txt`。本结论证明此次换线后的实际链路恢复，不承诺所有未来线材、接口或系统版本永不发生断连。
