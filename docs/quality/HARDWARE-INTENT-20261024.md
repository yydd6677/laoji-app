实施 2026-10-24，跨零点于 2026-10-25 收尾。当前 worktree `vnext/implementation`；保留全部既有脏工作，不提交或推送 Git。不改服务器进程、模型、GPU 分配或网络设备。

## 本轮实现

- 按键生产 C owner：40 ms 去抖、800 ms 长按、320 ms 双击。待机长按会议、双击日程、短按无操作；录制/暂停中短按暂停/继续，长按结束，双击不改变用途。上电按住、长按后的松手不误触。队列按钮绑定采集会话及有效期，不影响后来的录音。
- 用途、不可变采集 ID、原始时刻和 IANA 时区存入 RIFF `ljct`，不是缓存、文件名前缀或 PCM 包头。224 字节新头兼容现有 RIFF 解析，旧 44 字节录音继续读取/恢复。
- 原生完整文件仍经长度、generation、PCM SHA 校验。`PendingHardwareRecording` 同时保留容器 SHA 和音频 SHA；日程幂等按设备 + capture_id + 音频 SHA，避免不同传输容器制造重复业务对象。
- 会议继续自动入原链；日程不创建 Meeting/RecordingAsset/CAM++ 任务。新增日程库 schema 3 持久输入任务，复用已有确认、补充、详细编辑、保存和日历投影。
- 文件补处理统一为原生有界 PCM producer → 现有日程 WSS → 同一 `parseText`。真实测试发现旧 `/schedule/parse-audio` 返回 426，已删除手机端旧 HTTP 调用和专属解包/文件名函数，不恢复旧服务，也不添加第二套 parser。
- WAV 读写/校验从硬件专属文件提升为共享 `audio/PcmWaveFile.kt`，原测试同步移动；手机语音补处理与板端日程共用同一 source adapter。
- 未确认输入保留来源和草稿，关闭或退出不丢；日历提供待确认入口。保存请求 ID 固定，回执完成后清理交接音频与草稿正文，重收不会重新建日程。失败保留源，有限自动重试后仍可重试或删除。
- 设备状态、通知与帮助区分日程/会议，不增加硬件专用日历页、自动分类模型或旧手动加入会议步骤。产品/UI skill 已按新边界同步修订。
