# 会议问答：精确引用与候选淘汰

承接 `PHONE-20261022.md` 和 `Q2-LATENCY-20261022.md`。本轮只交付引用展示及校验修复，不宣称长会议问答质量已经闭合。未提交或推送 Git。

## 已采用

- 本机引用身份改为来源类型、来源 ID、revision、内容哈希、UTF-8 范围和引用哈希的组合，不再把分句内 citation ID 当作证据身份。同一原文被多个分句引用时只展示一次；不同位置的同字原文仍是不同证据。
- 每条引用展示经过校验的逐字范围，不再展示整份来源的开头。转写、笔记、附件共用这一规则。去重前仍校验每一条引用，不能借重复项隐藏错误哈希。
- 服务端语义复核删除引用后，再核对剩余原文中的数字。失去唯一数值依据的分句不能继续展示；全部分句失效时返回有内容的 `cannot_confirm`，不能返回空答案。
- 不重写既有答案或 clause attribution，不修改历史来源，不自动重新生成。新任务的生成提示词、生成 Schema 和语义复核实现保持原生产版；没有新增模型、模型调用、检索 fallback 或 GPU 分配。

## 候选为何没有发布

真实长会议的 225 段 Android ASR 与短会议 ASR／当前笔记分别回放 12 题和 8 题。字幕不替代 ASR，也不将题目答案写入生产提示词。

试验过逐原文原子复核、放宽空 answer 占位、全局片段 ID、问题焦点和证据排序。部分组合能找出原先漏掉的预付比例与综合条件，但完整复测出现新的漏答、归责错误或 grounding 错误，不能只选改善的题目验收。

特别是逐原文复核／空占位候选，把笔记第一人称错误归给会议发言人；强化来源身份约束后又将该题全部拒答。还有单价单位表述退化和无关附带内容。上述生成、Schema、排序和复核候选全部未采用，专属代码和测试已从活动源码移除；不是新增一条运行时备用链。

现有 Schema 的 answer 占位与提示词存在不一致，直接放宽确实会改变生成行为。该问题保留为下一次 Q2 协议重构的设计输入，不能把形式正确当作语义通过。下一片应重新收敛单一答案承载、来源身份和问答范围，再同时比较长短会议，而不是继续加入样本关键词补丁。

## 采用版的实际证据

- 最终采用版同输入回放：长会议 12 题、短会议 8 题全部完成，无接口／结构错误。87 个返回引用逐条检查了当前来源、UTF-8 范围、逐字内容和全文哈希，全部吻合；每分句最多 8 条引用。
- 长会议 12 个答案与上次生产基线逐字相同。预付比例、余款期限和综合条件仍不合格；短会议部分工作归纳也有遗漏。20 次请求完成和引用可解析绝不是 20 次语义合格，更不是人工 95% 通过。
- 短会议笔记任务仍归笔记中的“我”，没有被改归给发言人。采用版纯 reader 回放中位耗时长会议 7,422.5 ms、短会议 6,900.5 ms；不是手机完整等待，不作本轮提速结论。
- 专用 emulator-5562 打开既有问答历史：原中文回答的 6 条重复引用变成 3 条唯一证据，英文回答的 2 条不同证据保留。展开后实际检查了画面和逐条摘录；点击 14:22 引用进入当前文字记录的对应位置。没有改数据库答案或删除会议。
- 部署后 Android 实际 owner 通过生产鉴权、合并来源 POST、模型和本机 SQLite 完成一次新问答，共 18,052 ms，返回正确单价及 3 条唯一引用。只有两次 binding PUT 和一次问答 POST，均 HTTP 200；不把此单次计时称作 p95 或本轮加速。
- 后端聚焦回归 70 项、前端历史／引用／来源传输 20 项通过，TypeScript、UI 已知回归和连续性检查通过。mock 合同测试与上述真实模型／Android 回放分别记录，不混算质量通过率。

私有原始回放保存在本机 `output/q2-attribution-20261022/`。其中 `final-*`、`final2-*` 是被否决候选，只有 `adopted-long.jsonl`、`adopted-short.jsonl` 对应最终采用版。不能按文件名中的 final 误认为已经上线。

交付后删除本轮服务器 6.4 MiB 私有探针／来源／候选目录和本机 `/tmp` 候选源码。生产无新备用分支，没有遗留回放进程。
