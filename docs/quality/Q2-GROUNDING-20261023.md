## 确认的确定性丢句

当前生成协议每句最多两段证据，每段最多八个 ASR part；复核展开后，公开合同每句仍最多八条原始引用。两段各自合法不等于合计合法。

12 个长会议旧问题与 8 个短会议/笔记旧问题，使用完整保存的真实 reader/review 输出，逐个经当前代码重放：**20/20 最终 envelope 与已保存结果完全相等**，未调用模型/embedding，没有重做历史任务。

- 长会议：模型生成 26 句，进入复核 22 句，复核后 16 句，最终仍 16 句。
- 短会议：生成 15 句，复核前 14 句，复核后/最终 11 句。
- 只有一条旧回答触发本次关注的数量边界：两段共九条原始引用，模型复核 supported=true，但服务端因超过八条将整句省略。
- 该句仍只泛称预付“一定比例”，没有直接回答用户所问比例，并附带不必要的内容。因此**放宽为十六条不会自动解决质量问题**，反而可能增加用户不想看到的引用。本轮没有放宽公共合同，也没截断所需证据去强行通过。

不能从一次数量边界丢句推断所有漏答都由代码门禁造成。尤其旧版“未提及尾款期限”在生成阶段已发生，不能通过取消后置过滤修好。

## 未采用的实现切片

在私有候选中，将第二轮由“只能删除整句的语义审核”改为“重读完整规范来源并修订草稿”。仍为常驻本地 9B、两次生成；草稿不是事实来源，最终引用仍经过原 UTF-8/原文哈希/数值及八条上限校验。未使用样本关键词、外部答案、额外模型或生产 fallback。

按同一两段真实 Android ASR/笔记，先做六个关键旧问题，合计 **12 次真实模型调用**，不是十二个独立问题：

| 问题边界 | 实际表现 | 纯 reader wall time |
| --- | --- | ---: |
| 最终预付比例 | 补出正确比例，但附带不必要的尾款/金额缺失描述 | 12,859 ms |
| 余款期限 | 补出验货后五天，也附带预付比例 | 6,860 ms |
| 综合达成条件 | 仍漏付款条件，并新增无据的“验收标准等细节达成一致” | 11,867 ms |
| 最终单价 | 保持正确，但重复同一单价并附带批量信息 | 14,232 ms |
| 笔记安排和执行者 | 保留笔记中的“我”，未错归发言人；没有提速 | 12,978 ms |
| 不存在的电话号码 | 首轮正确拒答，第二轮却返回 answer+空 clauses，触发 `Q2_GROUNDING_INVALID` | 3,173 ms |

因此在六题即停止候选，不继续围绕原题调提示词凑通过率，也不补第三轮去遮住错误。已有基线相应六题为 10,089/2,406/10,262/9,311/4,915/1,512 ms；跨时段负载并非严格一致，不据此给精确因果倍数，但没有整体提速证据。更不能把五次正常返回称为五次语义合格。

失败候选源码已从活动目录移除；未新增备用链路或专属生产开关。小型私有真实调用输出留在 `output/q2-grounding-20261023/revision-*.jsonl`，不进入 prompt/源码。

## 保留的开发工具

`tools/quality/replay_question_grounding.py` 用当前真实 reader/复核处理保存的模型调用，输出生成、复核前/后、最终句数及引用展开数量。它复用真实校验 owner，不另写一份“更容易通过”的判定。

- provider 只能返回捕获值；捕获不够、顺序不符、有未消费调用或需要未捕获 embedding 时失败关闭，不偷偷访问服务。
- 逐字比较完整最终 envelope；不能只比较 answer_kind 或 HTTP 成功。
- 报告不含问题正文、答案正文、引用原文、人物或来源 ID。私有输入保持原保存位置，输出权限 0600。
- 工具六项回归区分正常拒答、九条引用导致的整句丢失、八条引用正常保留、未捕获调用、未消费捕获及超长输入意外访问 embedding；异常也恢复被临时替换的函数。
- 这是确定性调试/回归证据，**不是实时服务、自然语言新样本、人工评审或语义质量门**。
