# 日程解析质量提升指示（v6）

## 目标与边界

本工作包针对老记“语音新建日程”链路的结构化解析质量，重点解决重复日程被降级为一次性、重复字段丢失、ASR 口语噪声污染标题/日期、日期边界不稳定和地点误提取。目标是让可确定的表达快速、可重复地解析，让不可安全表达的规则返回中文澄清，而不是静默生成错误日程。

本指示覆盖三层：

1. 服务端确定性解析器：`/home/yydd/LaoJi/server-staging/qwen35-9b-cutover/smart-meeting-ai/backend/app/services/schedule_parser_service.py`。
2. 移动端本地解析器：`src/services/localScheduleParser.ts`，只承担本地安全子集；不确定项必须交给服务端。
3. API 与保存链路：重复字段必须完整传递并持久化，不能只传 `event_type`。

模型输出只作为复杂表达的补充。确定性重复规则优先于模型，避免模型超时、输出偏 JSON 或自由发挥时把重复事件变成 once。

## 当前实现结论

本轮已实现：

- `recurrence_interval`、`recurrence_weekdays`、`recurrence_until_date` 的服务端解析、归一化和移动端传递。
- 每天/每周单日/多星期/星期范围/工作日/周末/隔 N 周/每 N 个月/每 N 年。
- 明确结束日期保留为重复截止日期；不支持的“每月最后一个工作日”“每月第一个周一”“节假日排除”“重复 N 次”等规则返回中文澄清，禁止静默变成 once。
- 每月和每年事件滚动到参考日期之后的下一次发生日。
- 紧凑星期表达（例如“每周一三五”）和带分隔表达均完整保留星期集合。
- 句首及日期/时间附近的常见 ASR 填充词不会进入标题；下午时间保留为正确的 13:00-23:00 小时。
- “在研发楼 A301 会议室安排事项”这类地点与动作组合可提取完整地点，标题中的“地点会议”不会伪装成地点。
- 两位月份日期校验避免从 `10月` 截取为 `0月`。
- 模型结果归一化测试使用请求参考时钟，`下周一` 不再受本机当前日期影响。
- Ollama 不可达时，复杂但可由规则安全确定的请求会走确定性回退，不会直接丢失可澄清草稿。
- 更正表达优先采用最终时间和最终地点；不确定地点不再作为可保存地点；繁体字形 `週/點/號` 会先归一化。
- 无日期草稿补齐重复字段，非法日期的计时草稿仍保留安全的中文澄清和默认提醒。

当前没有宣称：远程 `18035` 已部署本轮源码、真实 ASR 音频质量、线上模型延迟或真实用户影子流量质量。远程 SSH 未通过 BatchMode 认证时，不能把本地候选测试当成远程服务验证。

## 失败分类与迭代规则

每次运行只按失败簇修复，不通过降低断言标准“修绿”：

- `field:event_type`、`field:recurrence_interval`、`field:recurrence_weekdays`、`field:recurrence_until_date`：C0，优先修复；任何明确重复表达降级为 once 都阻断发布。
- `field:start_date`、`field:end_date`、`unsafe_empty_start`：C0；日期错误或可保存日期为空时阻断发布。
- `field:needs_clarification`、`field:clarification_contains`：C1；复杂规则必须有中文澄清，且不能带可保存的错误日期。
- `field:title`、`field:location`、`field:start_time`、`field:end_time`：C1；ASR 噪声和地点错误会直接影响用户可见结果。
- `field:category`：通常为 C2，除非它改变了提醒或安全路由；必须单独统计，不得掩盖 C0/C1。
- `expected_null`：C0；解释、测试、取消、举例不能创建日程。

迭代顺序固定为：复现单条 -> 判断测试期望是否合理 -> 写最小回归 -> 修 parser -> 跑对应 family -> 跑 720 全量 -> 跑 10k 分层批次 -> 跑 10k 全量 -> 跑冻结回归。每轮报告只保存 hash、计数和失败代码，不打印原始用户语音文本。
