# 飞书日历重构基线合同

更新日期：2026-07-15

## 权威边界

- 日历结构、通用 UI 组件和页面动效以飞书 Android 7.71.8 的 Java/XML/资源为首要参考。
- 基线 APK SHA-256：`3355a2a53543ae1a68fe10844b8ed9884fffa7d1eafdc6bf8622180e43631447`。
- 截图只用于交叉检查视觉结果，不替代源码和状态合同审阅。
- 旧 Figma Make 页面与旧粉紫色老记日历不再是日历重构权威。
- 老记独有的语音创建、会议录制、转写和总结按自身任务合同验收；可借用飞书通用容器机制，但不强行复刻不存在的页面。

## 产品例外

1. 只保留月视图和单日视图；视图按钮直接切换，不打开飞书侧栏。
2. 一周固定从周日开始。
3. 不增加显式“回到今天”按钮。
4. 第一版事件统一主色，不按分类着色。
5. 不实现多日历、日历账号、三日/列表视图和六入口底栏。
6. 不复刻参与人、会议室、群聊、RSVP、签到和飞书会议联动；老记会议模块保持独立。
7. 底部只保留“日程”和“会议”。
8. 语音创建必须保留，并最终与手动创建共用草稿校验和唯一保存入口。

## 审阅规则

- 飞书能力缺少但属于上述裁剪时，标为产品例外，不标成视觉缺陷。
- 当前代码与飞书已保留能力不一致时，记录源码证据、当前证据、期望行为和可执行验收。
- 反编译无法还原的原生/Rust 算法必须通过真实响应或真机 fixture 验证，不能按猜测实现后宣称 1:1。
- 交互正确性以状态和手势测试为主，截图只检查少量高风险布局。

## 发布前硬门禁

1. 当前运行依赖的源码、测试和公开合同必须进入版本控制，并从干净检出重跑 TypeScript、Jest 和 Android release 构建。
2. 重复日程使用稳定的系列 ID 与 occurrence 日期引用，搜索、详情、编辑、删除和提醒共享同一合同。
3. 冲突检测按目标日期范围查询，覆盖重复实例和已确定的全天语义。
4. 删除、撤销、提醒取消及失败回滚具有确定事务结果。
5. 通知在前台、后台和冷启动时都能回到正确日程详情，注册表故障可恢复且不产生重复提醒。
6. 月份缓存有边界，加载/错误按范围隔离，前台恢复刷新云端月数据和搜索目录。
7. 月/日切换、快速年月、搜索详情、时段创建、跨午夜、复杂重叠、滚动位置和 TalkBack 有对应验收。

## 个性化入口

日程加号短按保留可发现的语音/手动选择面板；长按后提供四分之一圆弧拖选快捷方式。语音页的详细布局、手势、状态和性能验收见 `docs/voice-schedule-interaction-contract.md`。
