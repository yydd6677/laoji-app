# 设备整理持久任务真实回归（2026-08-10）

## 测试范围

使用一次性临时设备和 20 秒真实会议视频音频片段，走公网设备链路：注册、会议绑定、资产登记、两段二进制分片、合并、Qwen 转写、设备整理、整理结果读取和 epoch 删除。探针使用与普通命令行客户端一致的 User-Agent；首次 Python 默认 User-Agent 被 Cloudflare 1010 拦截，未到达 API，不产生设备数据。

## 结果

- 注册 `201`，会议绑定 `201`，能力 `200`。
- 两个分片均 `200`，合并 `200`，转写提交 `202`，最终转写 `completed`，得到 6 条文字。
- 整理提交 `202`，任务最终状态 `SUCCESS`，结果读取 `200` 且包含结构化整理文档。
- epoch 删除 `200`，并返回 `summary_tasks_deleted=1`。

## 清理复核

关闭后的临时 epoch 状态为 `deleted`；会议、资产、转写、整理任务、源路径和声纹 profile 均为 `0`。公网 `/api/ready` 仍为 `ready=true`，队列为 `0`，数据库检查为 ready。

该回归证明“只有 `device-*` 任务持久化”的修复没有误伤设备整理重启/轮询所依赖的任务表；临时音频和生成任务在 epoch 关闭后没有残留。
