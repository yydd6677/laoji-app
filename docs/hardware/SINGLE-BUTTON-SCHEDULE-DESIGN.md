# 单键会议与日程：已采用的合同

用户于 2026-10-24 选择明确手势分流，取代“按住口述、松手结束”的旧候选。实施证据见 [验收记录](../quality/HARDWARE-INTENT-20261024.md)。

| 状态 | 短按 | 双击 | 长按 |
| --- | --- | --- | --- |
| 待机 | 无操作 | 开始日程语音 | 开始会议录音 |
| 录音 | 暂停 | 无操作 | 结束并保存 |
| 暂停 | 继续 | 无操作 | 结束并保存 |
| 保存、传输 | 不抢占 | 不抢占 | 不抢占 |

GPIO38 低电平按下，40 ms 去抖、800 ms 长按、320 ms 双击窗口。长按在阈值执行，松手不追加短按。按住上电必须先释放。队列事件绑定原会话及有效期，不控制后来的录音。BOOT、复位、电池开关不复用；用途只属于本次录音，不保存“上次模式”。没有确认可用的硬件灯或振动，不编造输出引脚。

## 融合现有链路

两用途共用 ADC、FIFO、唯一 SD 写者、SHA、实时 PCM、补读、Wi-Fi 和原生接收队列。不依据时长、关键词或内容猜用途，不增加分类模型。

- 会议照常自动接入 Meeting / RecordingAsset，实时接回同一根，离线创建会议；不恢复“手动加入会议”。
- 日程不创建会议、不调用 CAM++ 或会议整理。完整音频进入日程库持久输入任务；现有日程 WSS 转写后调用同一 `parseText` 规则 / MentionGraph 路由。手机语音的文件补处理也用这一入口，不恢复已退役的 HTTP parse-audio。
- 使用现有日程确认、补充和详细编辑。明确保存前不写日历；同一来源使用稳定请求 ID，重试不能重复创建。
- 关闭确认页保留草稿；日历提供待确认入口。保存或明确删除后留下无正文幂等回执，清理手机交接副本，不暗删 SD 源文件。
- 不在后台或锁屏强制跳页，已有输入不被顶掉。日期仍是保存的必要字段，标题、钟点不增加强制要求。

## 来源与恢复

控制 JSON 增加 `purpose=meeting|schedule`、不可变 `capture_id`、`created_epoch_ms`、`time_zone`；20 字节音频帧和 6 字节控制分片不变。

标准 RIFF 新增 172 字节 `ljct` 来源块，头长 224 字节，PCM 仍为 16 kHz 单声道 PCM16。用途、ID、采集时刻与 IANA 时区随文件持久保存，改名、重连、掉电恢复不依赖文件名推测用途。旧 WAV 仍为会议；损坏来源块或未知用途不得静默变会议。

日程幂等身份为设备 + capture_id，使用音频 SHA 而非容器 SHA：BLE 重建 WAV 与 Wi-Fi 原文件的容器不同不能制造第二条日程。冷启动离线未校时则补充日期，不用接收时刻解释“明天”。

任务与草稿写独立 `laoji-schedule.db`，会议库不持有日程输入；不增加跨库事务或云端日历。源音频留到保存/删除，失败可重跑。

## 证据边界

实际生产 C 函数覆盖去抖、长短双击、上电按住、松手消费和动作矩阵；实板检查两用途、暂停恢复、PCM SHA 和改名后来源。模拟器检查原生接收、真实语音服务、解析、确认、保存和重进。实体按键、手机物理 BLE/Wi-Fi 必须单列，不能用模拟器或 Linux 回放冒充。发布须核对公开清单及完整 APK 下载 SHA。
