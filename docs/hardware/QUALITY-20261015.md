## 2026-10-17 实时链路改进检查点

本轮先闭合实时链路，不把问答和板端问题混入通过数。

- **已部署 API 热路径修复**：v2 身份、Task、Realtime 的加法 schema 初始化按数据库实例缓存；数据库替换、切换、显式 reset、进程变化和失败重试仍会重新初始化。只缓存 DDL，不缓存鉴权、绑定、任务 fence 或正文。把旧初始化中的终态 attempt 修复拆为显式启动恢复。相同运行环境、10 次检查的 p50 从 16.011 ms 降到 0.243 ms，max 0.364 ms；这不是端到端延迟值。
- **复测发现并修复容量泄漏**：两条数小时前遗留的 `open` 会话占满设备名额，API 明确返回 `REALTIME_CAPACITY_BUSY`，实际没有运行中的 attempt。容量现在由原 session 行中的短期 worker admission 控制（90 s、25 s 续租）；旧 worker 的断线不能释放后继连接，过期 worker 不能继续发布。普通断线只释放名额，不删除 PCM、事件或可恢复任务。持续连接同时续租原 Task attempt，暂停不会因无音频被误回收。API 保留运行态已有 capability barrier，未整体覆盖部署文件。
- **原生传输候选已落地**：无损聚合约 500 ms PCM 后再进行加密、fsync 和游标持久化；保留末尾不足 1 ms 的完整采样，结束时与最后一包合并，不补静音、不丢字节。可重建索引取代逐 ACK 全目录扫描；AES-GCM、原子提交、累计 ACK、重放与顺序约束不变。新增约 0.5 s 的聚包上限是明确代价，不以聚包宣称识别窗缩短。
