## 验证边界

1. 真板中继：Android 原生 GATT → netsim/Bumble → Linux BLE → 实板。控制内容、源偏移、PCM、元数据及 SHA 原样传递；只重做传输分片。不改 hello 能力、不伪造固件。这个边界可验证 App 与实际固件合同，但不能证明手机物理无线或系统热点授权。
2. 虚拟外设：只用于确定性故障注入、可重复的人声输入和大文件错误合同，不算实板证据。
3. 真实服务：加入会议后调用现有上传/ASR/整理/问答服务；不使用预置结果。

当前外接录音在录制中只接收本地 PCM/音量；结束后校验并加入会议才触发转写。不得把这一流程称为板端实时转写已完成。

### 本轮修正及门禁

- 接收身份改为 device + recording ID + generation，删除按 session/文件名误判“已接收”的路径；3 项回归用例。
- 外接页控件显式使用主题字体与正确行高，标题输入保持垂直居中；“加入会议”保留足够宽度，不换行裁切。
- 重命名时键盘不再吞掉保存按钮的第一次点击；最后用虚拟外设、中文输入与打开的键盘重验，一次点击即发出 recording.rename，列表变为“标题保存验证”。
- 错误状态不再叠加两个同义“连接中断”；完整性/代际错误有简短可操作的中文结果，原生包装不外露；2 项回归用例。
- TS 排除固件 CMake 生成的 compiler_depend.ts，使前端类型检查检查真实 TS，而不是把生成依赖文件当源码。
- tsc、41 项 JVM 硬件测试、5 项 JS 回归和已知 UI 回归均通过。新增证据复核器核对 8 组已留存证据；这些不是 8 次独立设备测试，更不是全局质量通过率。

### 未关闭的缺口

1. 板端 live PCM 目前只落本地镜像和音量反馈，没有接入实时 ASR；结束、校验、加入会议后的转写已验证。不能把两个能力混称。
2. 本轮板端音频 RMS 约 37.7 / 32768，未形成可靠人声拾音证据。需正常距离讲话与手机联动验证，不据此单独判定麦克风或固件坏了。
3. 冷连接读取旧录音列表，首次 17 个文件的元数据阶段约 37 秒，后续冷重连仍可能超过 40 秒。当前 UI 等列表完成才释放操作忙状态，固件元数据缓存仅 16 项；应另做懒加载/缓存与控制优先级的性能改造，不能因录音命令本身快就称连接体验通过。
4. 18 秒片段的整理功能跑通，但部分候选把回顾性、宏观表达当行动。此轮没有调整生产提示词或关键词门禁，更没有为样本写专用规则；需要独立语义质量回归。
5. E05 大于 1 MiB 文件的 Android Wi-Fi 完整接收、物理 BLE、系统后台及真实按键仍需真机。模拟器中继的 Linux MTU 缓存与 Android 系统 Wi-Fi 授权不是同一验证边界。
