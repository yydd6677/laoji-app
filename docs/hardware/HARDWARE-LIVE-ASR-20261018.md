# 外接录音实时文字：候选实现与证据

## 范围

按用户最新决定，只验链路可用性；本轮不调整识别准确率、讲话人、整理或问答质量，不改服务部署、不刷板端固件。固件仍为 2.0.2 / BLE 1.3。下面的模拟外设与真实模型服务证据，不等于手机物理 BLE、系统热点或实体键通过。

## 单一所有者

- `HardwareRuntime` 继续拥有 BLE、录音状态、连续 PCM 镜像、SD 补读及全文件校验；录音不等待网络，也不调用手机麦克风。
- `HardwareRealtimeSession` 是文件支持的外部 PCM 生产者，复用 `DeviceV2RealtimeAsrSocket`、设备凭据租约、加密发送重放和稳定事件游标。服务未就绪时暂存真实 PCM；缺包封闭可信前缀，不拼接后续语音、不补静音伪造完整性。
- `HardwareRealtimeCoordinator` 全局负责投影，页面不拥有实时任务。一次板端 capture 对应一个稳定本地 meeting ID。稳定文字先提交 canonical SQLite，再确认 native outbox；仅预览的 partial 不落权威文字。
- `canonical-live` 是可变本地草稿，`remoteRevisionId=null`。不得把 session ID 或递增 cursor 当作不可变远程文档版本，否则第二批会被既有不可变校验拒绝。
- 录音结束、完整 WAV 校验通过后，pending 索引记录 `captureMeetingId`，自动导入同一条会议。自动导入复用现有 ingest journal / R2 / 最终转写，asset ID 使用稳定的 pending ID，不抢走用户当前导航。普通卡上存量录音仍走既有手动加入流程。
- `audioReady` 只能由完整性通过的 pending 索引推进。恢复时重新核对索引，修复索引已提交而投影未完成的窗口；未验证的 live prefix 不让会议提前进入本地录音完成态。
- 已完成 final 永远优先于晚到 live draft。单条投影失败不阻塞其他会话；清除本机数据先撤销外部生产者，旧异步回调受清除代际约束，不能重新创建已清除会议；不删板上 SD 文件。

## 展示

外接设备页录音控件下仅在有内容时显示最多三行实时文字，沿用当前主题字体；控制区在文字增长时不移动。没有新增常驻空白行、全局状态或教程。缺包/实时服务不可用时单独说明“实时文字暂不可用”，不冒充录音失败，也不替换最后可读文字。设备“接收”按钮保证最小宽度，避免只露出一个字。

## 本轮实测

1. 原生 JVM 新增 12 项测试覆盖连接前缓冲、末段排空、缺包与错位、暂停恢复、发送游标恢复、稳定事件去重、显式确认、进程恢复元数据、传输失败不结束采集，以及原始 capture ID / 设备 / 文件 / 代际隔离。与原有硬件测试共 56 项，零 failures/errors。重连后收到结束事件时，以原始 capture ID 关联最终 generation；不凭文件名猜测。
2. 新增 7 项 TS/Node 投影与清除代际测试；加已有身份/中文错误共 13 项通过。TypeScript 和 UI 已知回归/连续性检查通过。
3. `emulator-5562` 经 Android 原生 GATT 连接虚拟 BLE 1.3 外设，输入既有 18 秒人声 WAV，实际调用 `laoji.cloud` 的 device-v2 实时服务。没有预置转写响应或把样本文字写入生产逻辑。
4. 最终成功录制根 `9ebeef3f-c4aa-3afe-90b1-ff0f19008629`：停止前连续四次采样均为 `recording / streaming / hasGap=false`，预览文字持续变化；本地累计 4 段 live draft。停止时刻为 epoch ms `1792325979705`，采样范围 `1792325926509–1792325932557`，因此不是录后整批结果。
5. 停止后同一个根收到一个完整本地 WAV（2,098,220 bytes，一个资产），自动上传并激活 final（5 段，`completing=false`）；未额外创建第二条会议。pending 转写任务最终为空。
6. 另一轮真实请求出现超时，录音仍可暂停、停止并形成完整本地 WAV（705,580 bytes，同根一资产）；服务恢复后完成最终转写。这证明本轮请求失败没有破坏本地采集/保存，不等于已验手机飞行模式或路由器断网。
7. 首轮曾出现 live 缺口并成功由 SD 补齐，之后暴露草稿版本和 capture 完成投影的两个错误。它是修正前失败证据，不计入最终通过；错误没有成为部分音频导入或伪造 full transcript。

证据为工作树私有目录 `output/hardware-live-20261018/`：`live-progress.json`、`live-chain.mp4`、`streaming.png`、构建/门禁日志。样本只用于测试；不得公开上传用户音频、原 Flash/NVS 或带凭据的环境文件。

## 尚需关闭

- 当前候选 APK 的实体键启动/长按/连按；App 控制的物理 BLE 正常路径已通过，见下节，不能由此推导实体键也通过。

- 断连后板上独立结束、且 App 没有收到 `capture.finished` 时，不得仅凭文件名猜测已完成 generation 关联。未获得身份依据时保持手动接收，不虚报无条件自动恢复。
- 本轮不验准确率、延迟分布、长跑、低电量或正式硬件安全能力。正常文件链路通过不代表这些项目通过。

本候选尚未公开发布；不把已安装候选写成当前公开版本能力。
