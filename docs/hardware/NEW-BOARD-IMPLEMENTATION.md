## 硬件依据

- BOM：U102 ESP32-S3R8，U104 GD25Q64ESIGR，U301 ES7210，MIC301/MIC302 ZTS6216；与实测 8 MiB Flash、8 MiB PSRAM、16 kHz 单声道格式相符。
- MCU 页：I2C GPIO1/2；I2S DI/WS/BCK/MCK=10/11/12/13；SDMMC DAT0/CLK/CMD=14/21/47；BTN101=GPIO38，BOOT101=GPIO0，复位位号在文档为 RTS101（此前按照片读成 RST101）。USB D-/D+=19/20。
- Power 页：SW201 位于电池供电选择路径；图中 VBUS 经 D204 到 VOUT，VBAT 经 SW201/Q201 构成另一供电路径。VBUS/USB_VBUS/VCC_5V 的完整连接仍需 PCB 网表核对；不从 PDF 补全缺失连接。USB 下拨动不中断主控已实测。U204=TP4054；GPIO3 接充电状态，GPIO4 接 VBAT 分压。不因有接线而擅自声明固件已支持电量或关机。
- Interface 页 CN401=6 针扩展/显示接口，第二块实物有飞线，实际飞线端点仍不由原理图推定；SDMMC 用 1 bit，而非旧板 SPI 引脚。
- 实物与文件有位号/贴装差异时，保留差异，不据 BOM 当成全部已焊且可用。

## 实现边界

手机仅通过 BLE 控制/实时音频；可选 Wi-Fi 下载完整 WAV。USB 为当前板供电/调试口，不提供未经验证的手机数据入口。BLE 1.3 为唯一 wire contract，不保留 magic/CRC/旧 correlation 帧兼容分支。

按键协商在独立控制执行器处理，不在读线程阻塞等待响应；同一外接会话已有录音/传输则不接受另一条实时镜像，设备本地录音仍由设备自主决定。普通用户页面不显示协议/接线教程。

已连接的 BLE 会话由 connectedDevice 前台服务维持；只有录音/传输阶段持有短期续期的部分唤醒锁，断开即停服务。不得将此说成 Android 强制停止后仍能续录到手机；完整来源仍属于 SD 卡。

接收只公布通过长度、格式、版本和校验验证的完整录音。实时丢包后保留可信连续前缀并在停止后补读后缀；未完整时不制造完整会议。设备录音保持设备所有，不隐式删除、不发送旧 recording.ack。

若镜像长度正确但 SHA 不一致，丢弃镜像、完整重读设备 PCM 一次；再次不一致则失败，不重复无限重试。capture.finished 中的完整权威元数据直接用于本次会话，不在结束后再次全量 get。会话内元数据缓存用于列表/改名；每次传输仍校验 generation、范围和完整 SHA，断开清空缓存。

Wi-Fi 继续使用指定 Android Network，不切换全局网络。development_http 只允许当前 BLE 会话声明的本地 192.168.4.1；不全局放开 HTTP，不把该开发模式称为生产安全。

## 真机发现的问题与证据

- 实际广播只有 `LaoJi Test Board` 名称，service UUID 数组为空。扫描改为服务 UUID 或协议广播名，连接后仍严格核验 GATT/hello。不能以广播名当认证。
- 4 秒一次的页面本地状态轮询曾清空已取到的设备文件列表；现只在失去连接所有权时清空，ready/paused/recording/transfer 保留文件投影。
- 5.28 秒 / 168960 PCM bytes 和 18.528 秒 / 592896 PCM bytes 完整接收通过长度/SHA 校验；后者切到 HOME 后完成，回到页面仍为“已接收”。这是短期后台证据，不是长会验收。
- 1.2.14 镜像完成后有 `received_bytes=135168, expected_bytes=135168` 但 SHA 不一致；同一设备文件完整重读成功。1.2.15 新录音 `133120` bytes 触发一次 `pcm_integrity_refetch` 后自动完成接收。不得据此断定是手机、无线链路或固件中的哪一处改变了 PCM；底层差异仍待固件源码/双端字节对照定位。
- 1.2.15 板上 BTN101 触发录音成功，手机收到波形；较长录音结束后的 get 超过 8 秒，旧候选因此保留 SD 来源而未发布不完整会议。最终实现取消了该次重复 get，并为可能读 SD 的控制查询独立设置异步等待；这不等于板端查询性能已解决。
- 一条自建约 4 秒外接录音已从“待加入会议”进入会议详情，经过 R2 上传与 ASR 后得到 no_speech 终态，手机显示“未检测到人声”，未显示成处理失败。未提供真人语音，因此不能作为识别质量证据。
- 首轮 App 适配未刷写固件；后续已按用户单独授权试刷最小应用补丁。未格式化卡、删除设备源录音或清除手机已有数据。旧 LJHW 固件/脚本/USB 传输实现从活动源码移除，历史由 Git 保留；仅保存本次逆向修复必需的原应用读回以供恢复。
