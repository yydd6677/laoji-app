# 硬件接口

老记使用 BLE 1.3 与录音设备通信。BLE 承载控制、事件、实时 PCM 和已完成录音的区间读取；Wi-Fi 是可选的完整 WAV 下载通道。

## 文档

- [BLE 1.3 通信协议](BLE-1.3.md)：连接前提、帧格式、命令、事件、数据约束和能力扩展。
- [消息 Schema](../../contracts/hardware/laoji-hardware-control-v1.3.schema.json)：已知BLE控制/事件的操作名、公共类型及部分扩展约束，不用于HTTP响应。
- [ESP32-S3 参考固件](../../hardware/esp32s3-voice-memo/firmware/README.md)：板级配置、构建、模块和测试。

协议定义包含字段语义、状态与生命周期约束。Schema 仅覆盖其中一部分，不能单凭 Schema 校验结果判断设备是否完成适配。

## 必需能力

Android 接入要求 BLE 1.3、Control RX/TX、Audio TX、`development_ble` 安全模式、本地录音存储及 BLE 录音读取。音频格式为16kHz、单声道、16-bit little-endian PCM。握手完成后，App执行校时和状态查询。

Wi-Fi、列表预览、实时范围恢复和日程用途扩展的启用条件分别见协议第9、8.1、16和17节。设备只声明实际支持的能力。

## 业务接入

会议录音和日程语音通过明确的 `purpose` 区分，不以内容或录音时长判定用途。参考按键配置为待机长按开始会议、双击开始日程，录制中短按暂停/继续、长按结束。

文件接收完成后，App依据采集身份进行去重，并将录音交给会议或日程流程。日程须经用户保存后写入日历。用途、原始采集时刻、时区与RIFF上下文定义集中在协议第17节。

## 设备边界

参考固件使用 development BLE/HTTP，不提供生产级配对或端到端加密。USB用于调试和刷写，不承载手机音频传输。

其他PCB需要配置供电、引脚、codec、存储与按键，并验证控制、音频完整性、断连恢复及声明支持的可选能力。参考刷写工具有板型和分区保护，使用前须核对设备配置。
