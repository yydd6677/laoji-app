# 新板硬件适配基线

唯一硬件目标：ESP32S3 语音备忘录 V1.0。唯一线协议：[BLE 1.3](BLE-1.3.md)。旧 PD-AILAMP-D01 测试板实现已退出活动代码，不保留兼容路径。

## 硬件与固件分层

设计文件为 2026-09-14 原理图、2026-09-17 BOM/PCB。主控 ESP32-S3R8；8 MiB Flash GD25Q64ESIGR；ES7210 + 两颗 ZTS6216；GPIO38 功能键、GPIO0 BOOT、CHIP_PU 复位；SDMMC DAT0/CLK/CMD=14/21/47。

原理图中复位位号为 RTS101，此前按照片标为 RST101；两者指同一已验证复位按钮。SW201 在电池供电路径，图中 VBUS 经 D204 到 VOUT，VBAT 另经开关/Q201 到供电通路。VBUS/USB_VBUS/VCC_5V 的完整命名连接仍需 PCB 网表确认，不能仅凭 PDF 推导全部供电细节。硬件有 TP4054、GPIO3 充电状态和 GPIO4 电池分压，但当前固件未开放电量/软件关机，App 不展示伪电量。

显示扩展 CN401 与第二块实物飞线需单独核实；不宣称装有屏幕。原应用 `usb_wireless_disk` 与旧型号自报仅作历史证据，不成为手机型号白名单。2026-10-17 起活动固件是独立源码工程 `hardware/esp32s3-voice-memo/firmware/`，自报 `laoji-recorder-2.0.0`；不再从原应用镜像打补丁构建，见 [完整源码固件](SOURCE-FIRMWARE-2.md)。

## 当前应用链

`BLE 1.3 控制/音频 -> generation + PCM/长度/SHA 校验 -> 本机完整 WAV -> HardwareRecordingStore -> 按持久 purpose 进入现有会议或日程 owner`

2.2.0 的长按会议 / 双击日程、RIFF 来源与独立日程任务见 [单键合同](SINGLE-BUTTON-SCHEDULE-DESIGN.md)。日程不创建 Meeting、不经过会议整理；语音识别后复用同一日程解析、补充和确认，收到会议录音仍自动入库。

- Control TX：6 字节分片头 + 一次 8 字节 JSON 头；按 command_id/op 关联响应。
- Audio TX：每次 Notify 是 20 字节头 + PCM，不做 JSON 分片重组。
- 连接后必须校时；按键协商由原生控制执行器直接响应，不经 JS 往返。
- 录音/传输状态由 HardwareRuntime 单一维护；只有真实开始/结束事件推进录音状态。
- 会议用途接收即自动保存，无手动“加入会议”、待加入列表或旧流程开关。实时录音接回原会议，离线接收按稳定源 ID 建立会议；沿用标题和日期，无需配置保存位置。日程用途交接给日程持久任务，进入已有确认/补充/编辑；不创建会议。交接副本只在会议资产或日程处理回执持久完成后释放，失败不丢源、不重复创建、不强制跳页。
- 录音文件名可以是中文；列表先取 ID，再 get 元数据；改名传 new_recording_id，成功后重新查询，不假定返回新对象。
- 实时只保存连续可信前缀，缺包后停止拼接，结束后按源 PCM 偏移补读；完整长度、generation 和 SHA 均通过后才成为可导入录音。断连不把不完整镜像伪装完整会议。
- 文件导入不发送旧 recording.ack，不隐式删除设备源文件。
- BLE 可以读取 PCM 并重建 WAV；大文件可走 Wi-Fi 完整 WAV，使用 Android 指定 Network，不切全局网络，不全局放行明文。
- USB 仅按当前实测视为板子供电/调试口；手机界面不提供未验证的 USB 连接。

## 验证边界

手机 1.2.21 / 229 已公开发布；此前 hw5 的真机 BLE/Wi-Fi 接收通过记录保留。新源码固件 2.0 已编译、写入应用分区并完成真实 Linux BLE 核心流程与实时/SD 字节一致性验证；其 Android 端到端与实际 HTTP 下载须单独重验，不能继承旧固件的通过结论。

实现、原生单元测试、Linux 真板协议回放、Android 真机端到端验证分别记录，不相互替代。候选进度与缺口见 [实施记录](NEW-BOARD-IMPLEMENTATION.md)。不在没有手机验证时声称已验证手机后台录音、系统热点授权或完整会议链。
