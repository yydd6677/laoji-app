# 当前工作目标：以真机为最终验收基准的飞书源码驱动重构

更新日期：2026-07-17

> 历史状态说明（2026-07-16）：本文件保留此前功能与发布门禁记录，但其中 UI、交互、动画和技术栈相关的 `[x]` 不再代表飞书仿真完成。新的权威证据与状态分别见 `docs/feishu-source-map.md`、`docs/feishu-parity-ledger.md` 和 `docs/native-platform-architecture.md`；只有完成源码闭包、实现、源码派生测试和独立复审后才能重新关闭。

## 目标

以当前已连接的 USB Android 真机和真实 release APK 作为最终运行验收环境。先修复并在真机回归老记 Android 主页面白屏，再把老记 Android 移动端完善为内部 release 候选版。日历结构、通用组件和动效以飞书 Android 7.71.8 源码为基线，删除老记无法提供或明确不需要的协作能力；语音创建、会议录制、转写和总结保持老记自己的产品路径。

本阶段以 `docs/feishu-source-map.md` 登记源码证据，以 `docs/native-platform-architecture.md` 约束实现边界，以 `docs/feishu-parity-ledger.md` 记录唯一完成状态；运行覆盖按 16 个注册路由和 2 个 MainTabs 逻辑目的地计算。每个运行相关关闭项都必须有源码闭包、对应实现、源码派生测试，以及绑定同一 APK 哈希的真机行为证据。

模拟器、JVM、单元测试和 androidTest 用于快速发现缺陷、验证确定性合同和覆盖 API 兼容性，但只作为开发预检，不能代替真机关闭运行目标。白屏、18 个可达目的地、页面与手势、语音和会议、通知、恢复、分享及 OEM 行为统一进入 `docs/android-device-follow-up.md` 的真机最终验收。USB 临时断开时可继续开发和预检，但目标保持未完成，连接恢复后从未通过项续测。

详细产品例外与审阅规则见 `docs/feishu-calendar-baseline-contract.md`，语音入口见 `docs/voice-schedule-interaction-contract.md`。本文件是现阶段实施顺序和完成条件的权威清单。

## 真机完成定义

- 源码闭包、架构迁移、静态门禁、业务与状态机测试以及 API 26/30/33/35 模拟器测试先作为自动化预检；16 个注册路由与 2 个 MainTabs 逻辑目的地、冷启动、进程重启、前后台恢复、页面返回、Window Overlay、普通手势和 release APK 可安装性最终在当前真机关闭。
- `UI-ANDROID-COMPOSITION-001` 只有在当前源码构建出的同一份 release APK 于真机完成冷启动、双向 Tab、返回、前后台、强停重启和重复启动，并始终无白屏、空白内容或异常闪烁后才能关闭。
- 目标完成时交付的是“通过自动化预检，并通过当前 USB 真机完整验收矩阵的 Android 内部 release 候选版”。它不是全部 Android 机型认证或商店提交包；结论边界限定为当前真机、当前系统版本、当前导航模式和已记录场景。
- 自动化测试与真机验收都必须保留：前者负责确定性回归和跨 API 预检，后者负责最终运行结论；任何一方都不得替代另一方。

## 已确定产品决策

1. **语音保存路径**：保留语音确认页直接保存的快速路径，同时与手动创建共享同一校验器和事件仓库；“编辑更多内容”才进入完整编辑页，不为了代码复用强迫每次语音创建多跳一页。
2. **全天冲突语义**：全天事项与定时事项只显示软提示，不阻止保存；全天与全天、定时与定时按明确重叠规则提示。
3. **重复事件编辑范围**：实现“仅此日程、此后日程、全部日程”三种范围，再开放重复实例的拖动和删除。
4. **时区范围**：v1 按设备时区显示，数据模型先保留事件时区字段；独立时区选择器延后，不保留只有外观没有能力的入口。
5. **实施拍板机制**：审阅中仍需选择但不改变既定产品边界的技术与交互细节，默认采用审阅建议并直接落实到合同、测试和代码；只有新增能力、扩大服务端权限、改变已确认裁剪或发布边界时，才重新请求产品确认。
